# ЭПД Лайт

MVP SaaS-сервиса для подготовки, проверки и хранения **черновиков электронной транспортной накладной (ЭТрН)** для российского малого и среднего бизнеса.

> **Важно:** проект не является оператором ИС ЭПД, не подписывает документы КЭП и не отправляет сведения в ГИС ЭПД. Экспортируемый JSON и печатная форма — внутренний черновой формат MVP, а не официальный XSD/юридически значимый документ.

## Что уже реализовано

- публичный лендинг, FAQ, CTA, тарифы и правовые шаблоны;
- официальные ссылки на ФНС и Минтранс;
- регистрация/вход через Supabase Auth;
- безопасный демо-режим на `localStorage`, если Supabase не настроен;
- онбординг организации;
- dashboard;
- список черновиков с поиском, фильтрами, дублированием, архивом и удалением;
- 6-шаговый мастер ЭТрН:
  1. участники;
  2. маршрут;
  3. груз;
  4. транспорт и водитель;
  5. условия перевозки;
  6. проверка;
- автосохранение черновика;
- разделение замечаний на обязательные и рекомендуемые к проверке у оператора;
- статус «Готов к передаче оператору» только после заполнения базовых обязательных полей;
- юридические статусы «Передан оператору» и «Подписан/принят» недоступны без интеграции;
- печатное превью с watermark `ЧЕРНОВИК — НЕ ЯВЛЯЕТСЯ ПЕРЕВОЗОЧНЫМ ДОКУМЕНТОМ`;
- экспорт нормализованного JSON;
- CRUD-справочники контрагентов, транспорта и водителей;
- CSV-импорт контрагентов с предпросмотром и примером файла;
- форма заявки на подключение оператора ИС ЭПД;
- безопасная граница `OperatorAdapter` для будущей server-to-server интеграции;
- SQL-миграция Supabase с Row Level Security: пользователь видит только свои записи;
- офлайн preflight-проверка ключевых продуктовых и RLS-инвариантов.

## Быстрый запуск

```bash
npm install
npm run preflight
npm run dev
```

Без `.env` приложение запустится в демо-режиме. Данные будут храниться только в браузере.

### Supabase / PostgreSQL

Для локальной разработки можно использовать обычный Supabase-проект. **Для коммерческого запуска в РФ не размещайте базу с персональными данными российских граждан за пределами РФ без отдельной юридической проверки.** Практичный вариант — self-hosted Supabase/PostgreSQL в российском дата-центре либо другой совместимый российский контур.

1. Создайте проект Supabase (для разработки) либо подготовьте совместимый production-контур в РФ.
2. Примените миграцию `supabase/migrations/202609010001_init.sql`.
3. Скопируйте `.env.example` в `.env`:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

4. В Supabase Auth настройте разрешённые Redirect URLs для вашего домена.

## Проверка и сборка

Без установки npm-зависимостей можно проверить критические инварианты:

```bash
npm run preflight
```

Проверяются наличие ключевых экранов/статусов, watermark, запрет имитации юридических статусов, RLS для всех таблиц и права роли `authenticated`.

Полная production-сборка:

```bash
npm run build
npm run preview
```

Для SPA-маршрутов добавлены `vercel.json` и `public/_redirects`, поэтому прямое открытие `/app/...` не должно превращаться в 404 на Vercel/Netlify. В `.github/workflows/ci.yml` preflight запускается до установки зависимостей, затем выполняется обычная production-сборка.

## Интеграция с оператором ИС ЭПД

План и архитектурные ограничения находятся в [`docs/OPERATOR-INTEGRATION.md`](docs/OPERATOR-INTEGRATION.md).

Ключевой принцип: интеграция должна быть server-to-server. API-ключи оператора, сервисные токены и материалы КЭП нельзя помещать во frontend. В MVP реальная отправка намеренно отключена.

## Что нужно до коммерческого запуска

- выбрать аккредитованного оператора ИС ЭПД и получить API/партнёрский доступ;
- сопоставить внутреннюю модель ЭТрН с актуальными официальными форматами ФНС и провести валидацию XSD;
- реализовать подписание/маршрутизацию строго через разрешённый контур оператора;
- заполнить и проверить с юристом политику конфиденциальности, пользовательское соглашение и реквизиты;
- обеспечить выполнение требований 152-ФЗ, включая применимые требования к локализации баз персональных данных граждан РФ;
- подключить реальный биллинг;
- провести интеграционные и security-тесты.

## Структура исходника приложения

Основной SPA-компонент временно хранится в читаемых частях `src/app-chunks/App.*.part`. Перед `npm run dev` и `npm run build` скрипт `scripts/assemble-app.mjs` автоматически собирает из них `src/App.tsx`. Сгенерированный `src/App.tsx` добавлен в `.gitignore`.
