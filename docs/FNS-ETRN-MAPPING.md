# ЭТрН КНД 1110339 — база маппинга ЭПД Лайт

Статус документа: **рабочая техническая база, не юридическое заключение и не спецификация оператора**.

Дата сверки источников: **01.09.2026**.

## Что подтверждено

ФНС указывает, что с 1 сентября 2026 года часть перевозочных документов переводится в обязательный электронный формат. На странице форматов черновиков ФНС электронная транспортная накладная указана с КНД **1110339**.

На той же странице ФНС опубликована XSD-схема черновика титула грузоотправителя с именем:

`ON_TRNACLGROT_1_973_01_05_01_02.xsd`

Из имени схемы и актуальной документации операторов следует используемая линия формата **5.01**. Документация Диадок для ЭТрН указывает тип `LogisticsWaybill`, версию `kl_trn_mt_05_01` и титул Т1 с префиксом `ON_TRNACLGROT`.

## Что намеренно НЕ делает ЭПД Лайт

До подключения реального оператора и финальной сверки XSD проект не должен:

1. Называть `Integration JSON` XML-документом ФНС.
2. Генерировать юридически значимый статус «передан», «подписан» или «принят ГИС ЭПД».
3. Хранить API-токены оператора, закрытые ключи или материалы КЭП в браузере.
4. Утверждать, что заполнение всех полей `operator-readiness` означает прохождение XSD.
5. Самостоятельно придумывать коды классификаторов, ID участников ЭДО или правила формирования транспортного контейнера.

## Два уровня проверки

### 1. Base readiness

Внутренний минимум ЭПД Лайт, достаточный для сохранения осмысленного черновика. Он включает участников, основные адреса, груз, транспорт и водителя.

### 2. Operator readiness

Набор полей-кандидатов, присутствующих в структуре Т1 и/или необходимых для последующего операторского маппинга. Отсутствие таких полей отображается отдельно. Нулевое количество замечаний означает только то, что **известные ЭПД Лайт поля заполнены**, а не то, что документ прошёл XSD.

## Следующая стадия после ответа ФНС/оператора

1. Скачать и зафиксировать конкретную XSD, принятую оператором для пилота.
2. Составить машинный mapping `OperatorDraftCandidate -> T1 XML`.
3. Добавить XSD-валидацию на сервере.
4. Добавить provider adapter (`kontur` или `taxcom`) и sandbox/test credentials.
5. Получать юридически значимые статусы только из ответа оператора.
6. Добавить журнал операторских запросов/ответов без хранения секретов и лишних персональных данных.
