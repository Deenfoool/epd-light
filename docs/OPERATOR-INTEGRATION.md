# Интеграция с оператором ИС ЭПД

## Решение для MVP

`ЭПД Лайт` не является оператором ИС ЭПД. Юридически значимый обмен должен идти через аккредитованного оператора, который передаёт сведения в ГИС ЭПД.

Для первого пилота разумно рассматривать операторов, которые публично предлагают API-интеграцию, в частности Контур.Логистику и Такском. Конкретный оператор выбирается только после получения коммерческих условий, тестового доступа и технической документации на актуальные форматы.

## Архитектурное правило

Интеграция должна быть **server-to-server**. В браузер нельзя помещать:

- API-ключи оператора;
- приватные ключи;
- материалы КЭП;
- сервисные токены с правом отправки документов.

Фронтенд передаёт нормализованный черновик в наш backend. Backend выполняет валидацию, преобразование в формат конкретного оператора, запросы к API и возвращает безопасный статус.

## Статусы

До подключения оператора доступны только внутренние статусы:

1. `draft` — черновик;
2. `incomplete` — требует заполнения;
3. `ready` — готов к передаче оператору;
4. `archived` — архив.

Статусы `передан оператору`, `подписан`, `принят ГИС ЭПД` нельзя устанавливать вручную или имитировать.

## План интеграции

1. Получить тестовый/партнёрский доступ оператора.
2. Получить актуальную API-документацию и требования к аутентификации.
3. Сопоставить `EtrnData` с актуальной официальной схемой ЭТрН и схемой API оператора.
4. Добавить XSD/форматную валидацию до отправки.
5. Реализовать серверный адаптер `OperatorAdapter` из `src/operator.ts`.
6. Добавить idempotency, журнал запросов и безопасное хранение внешних ID.
7. Реализовать polling/webhook статусов.
8. Отдельно реализовать сценарий подписания в соответствии с требованиями выбранного оператора.
9. Провести тестовый обмен и только после него открыть кнопку реальной отправки пользователям.
